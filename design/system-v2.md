# Workspace v2 design and interaction contract

Reference: workspace-v2.png. White #fff chrome, #f7faff pale canvas, #142454 ink, #64718b secondary, #e2e7f0 hairlines. Cobalt #2560ff primary; teal #159da1 and coral #f97366 logical object identity. DM Sans for UI, IBM Plex Mono for coordinates/time. 12–14px chrome, 24px main heading, 6px field corners. Outline Lucide 16px icons. Three open rails, not nested dashboard cards.

Header: SUPERPOSITION, editable project title, undo/redo, import/export/help. Left 236px scene and relation lists. Center flexible simulation canvas, transport, horizontal decisions strip. Right 292px context inspector. Bottom world/event explorer with real event timelines. Footer local-save and exact world counts. At narrower desktop use 208/264px rails; on mobile stack scene, canvas, inspector and explorer, preserving controls.

Required additions relative to concept: object duplicate/delete; relationship editor with source/target/event/action; world pagination/filter clearing; explicit per-option commit locks/reopen; JSON validation and import errors; unsatisfied event diagnostics. Exact physical values are pixel-based instead of misleading meters. No pan/zoom claim: object origins can be dragged or keyboard moved at t=0. Origins enabled by default for discoverability. All scene art is intentional code-native geometry. New starts an undoable blank scene. Event labels use accessible tooltips and the Events log instead of permanent text over densely overlapping timeline markers. The world count says “in view” to distinguish filters from total exact computation. The initial scene has one open dimension per object; the inspector can add a second.

The document is shared. Each object's impact behavior and release delay are independent choice variables. Preview filters never edit the document. Commit changes a choice binding only, preserving identities, edits, alternatives, and links. Worlds enumerate exact active combinations (maximum 128), never a hidden sample. All relations evaluate in each world's local event history. Follow uses a group centroid or largest fragment. Event edges must form a DAG; one active follow source per target. Fixed-step integration, cached 30Hz snapshots, deterministic rewind. Relationship contact uses bounding-circle overlap; objects sense overlap but do not automatically exchange rigid-body impulses.
